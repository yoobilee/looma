# 새 프로젝트 초기 설정 체크리스트

## 1. 기존 정보 확인

- [ ] 사용자가 이미 말한 요구사항을 정리하고 같은 질문을 반복하지 않는다.
- [ ] 프로젝트 목표, 대상 사용자, 주요 기능과 실행 플랫폼을 확인한다.
- [ ] 인증, 데이터 저장, 공개 범위와 필요한 외부 서비스만 조건부로 확인한다.
- [ ] 일정은 사용자가 제공한 경우에만 제약으로 반영한다.
- [ ] 예산을 기본 질문으로 요구하지 않는다. 비용 차이가 중요하면 후보 설명에 포함한다.
- [ ] 제공된 시안·레퍼런스 경로, 링크와 파일을 확인하고 출처를 기록한다.
- [ ] 시안이 없으면 시각적 방향을 사용자에게 확인한다.
- [ ] 새 화면이나 큰 UI 개편은 `.ai/policies/design-direction.md`에 따라 프로젝트 성격과 다른 레퍼런스를 폭넓게 비교한다.

## 2. 기술 후보 제안

- [ ] 프로젝트 구조에 영향을 주는 기술 스택 후보를 2~3개 제시한다.
- [ ] 후보별 적합한 이유, 주요 단점, 운영 부담, 비용 특성과 테스트 생태계를 설명한다.
- [ ] 웹·PC 환경 배포는 Vercel을 우선 후보로 고려하되 프로젝트 특성상 더 적합한 대안을 제시한다.
- [ ] 데이터 저장은 Supabase를 우선 후보로 고려하되 데이터 구조와 운영 요구에 맞는 대안을 제시한다.
- [ ] 사용자가 핵심 기술 스택, 배포 환경과 데이터 저장 방식을 확정하기 전에는 프로젝트 구조를 고정하지 않는다.

## 3. 프로젝트별 설정 작성

실제 구현을 시작하기 전에 이 절의 항목을 확정한다. 정하지 못한 항목은 `미정`으로 방치하지 말고 결정이 필요한 이유와 확인 대상을 기록한다.

- [ ] `AGENTS.md` 하단에 프로젝트명, 기술 스택과 선택 이유를 기록한다.
- [ ] 배포 환경, 데이터 저장, 외부 서비스와 레퍼런스 출처를 기록한다.
- [ ] 디자인 시스템 사용 여부, 브랜드 고유 요소, 화면 밀도·정보 계층·시각적 분위기와 피할 표현을 기록한다.
- [ ] 지원 기기·브라우저와 반응형·접근성 확인 범위를 기록한다.
- [ ] 패키지 관리 도구 하나와 잠금 파일을 확정한다.
- [ ] 설치, 개발 실행, Lint, Test, Build와 전체 검증 명령을 기록한다.
- [ ] 기본 브랜치, 버전 배포 여부, 버전 기준 파일과 태그 형식을 기록한다.
- [ ] 테스트 도입 시점, 테스트 도구와 백로그 위치를 기록한다.
- [ ] 클래스·함수·변수·컴포넌트·파일의 이름이 역할과 목적을 드러내도록 프로젝트 언어와 생태계에 맞는 명명 방식을 확정한다.
- [ ] 여러 Agent가 협업하는 경우에만 `.ai/policies/multi-agent-collaboration.md`를 읽고 역할, 전달 경로, 자동 진행 범위와 사용자 판단 조건을 기록한다.
- [ ] 자동 논의·수정·재검증이 이어지는 대규모 협업은 `.ai/templates/MULTI_AGENT_WORKFLOW.md`를 복사해 상태, 작업 식별자, 루프·비용·권한 제한과 단계별 도입 계획을 확정한다.

## 4. 저장소 초기화

- [ ] 프로젝트에 맞는 기술별 무시 항목을 `.gitignore`에 추가한다.
- [ ] 로컬에 빈 `.env`를 만들고 Git 추적 대상이 아닌지 확인한다.
- [ ] `.env.example`은 기본 생성하지 않는다.
- [ ] README, CHANGELOG, PATCH_NOTES, LICENSE와 CONTRIBUTING을 미리 만들지 않는다.
- [ ] 실제 구현을 시작하기 전에 새 작업 브랜치를 만든다.

## 5. 검증과 CI

- [ ] 로컬과 CI가 가능한 한 같은 전체 검증 진입점을 사용하게 한다.
- [ ] 선택한 기술에 맞는 Lint, Type Check, Test와 Build를 구성한다.
- [ ] 아직 없는 검사는 조용히 통과시키지 않고 `not configured`로 드러낸다.
- [ ] GitHub Actions CI가 PR에서 자동 실행되게 한다.
- [ ] 필수 CI 작업은 조건부로 건너뛰지 않게 한다.
- [ ] 기본 브랜치 직접 push 제한과 필수 상태 검사를 저장소 설정에서 확인한다.
- [ ] CI/CD 변경은 높은 위험이며 사람 확인 대상임을 유지한다.
- [ ] 리뷰 자동화를 도입하는 경우에만 `.ai/policies/review-automation.md`를 읽고 `AGENTS.md`의 리뷰 자동화 설정과 실패 시나리오 검증을 완료한다. 미사용이면 이 항목은 해당 없음으로 기록한다.

## 6. 시작 준비 완료

- [ ] 공통 규칙과 프로젝트별 규칙 사이에 모순이 없다.
- [ ] 비밀정보가 저장소에 포함되지 않았다.
- [ ] 최소 기능의 범위와 완료 조건이 명확하다.
- [ ] 첫 작업의 위험도를 정했다.
- [ ] 로컬에서 실행 가능한 초기 검증을 완료했다.
