# 디자인 방향 정책

## 적용 범위

- 새 화면, 랜딩 페이지, 서비스의 첫 UI와 큰 규모의 UI 개편에 적용한다.
- 문구, 작은 CSS 수정과 기존 패턴을 그대로 따르는 저위험 변경에는 긴 조사 절차를 강제하지 않는다.
- 시안이 있으면 시안을 우선한다. 시안이 없으면 조사 결과와 선택지를 제시해 사용자와 방향을 확정한 뒤 구현한다.

## 1. 레퍼런스 편향 방지

- “깔끔하게”, “요즘 트렌드에 맞게” 같은 요청을 특정 유명 서비스의 스타일로 자동 해석하지 않는다.
- Linear, Notion, Toss 등 자주 언급되는 서비스만 반복해서 기본 참고 대상으로 삼지 않는다.
- 프로젝트의 목적, 대상 사용자, 사용 환경과 핵심 행동을 먼저 정리한 뒤 관련 제품을 찾는다.
- 같은 업종뿐 아니라 정보 구조, 상호작용이나 사용 환경이 비슷한 다른 업종도 살핀다.
- 국내외 사례, 운영 중인 제품, 디자인 시스템과 실험적인 사례를 필요에 맞게 섞어 비교한다.
- 유행이나 수상 이력만으로 채택하지 않는다. 실제 사용성, 콘텐츠 밀도, 접근성, 반응형과 구현 비용을 함께 판단한다.

## 2. 레퍼런스 활용 방법

- 각 레퍼런스에서 참고할 요소와 참고하지 않을 요소를 구분한다.
- 색상, 구성, 타이포그래피, 아이콘, 움직임을 한 제품에서 통째로 복제하지 않는다.
- 여러 사례의 원리를 조합하고 프로젝트의 브랜드, 데이터와 사용자 흐름에 맞게 재해석한다.
- 출처 링크와 참고한 이유를 `AGENTS.md` 프로젝트별 설정에 기록한다.
- 라이선스가 있는 코드, 아이콘, 글꼴과 자산은 사용 조건을 확인한다. 이미지나 코드를 그대로 복사하지 않는다.

## 3. 디자인 시스템 선택

- 디자인 시스템은 일관성, 접근성과 구현 속도를 위한 기반이지 프로젝트의 시각적 정체성을 대신하는 완성 시안이 아니다.
- SEED Design을 포함한 기존 시스템은 기술 스택, 필요한 컴포넌트, 유지보수 상태, 호환성, 접근성, 사용자층과 브랜드 적합성을 비교한 뒤 선택한다.
- 특정 디자인 시스템을 모든 프로젝트의 기본 의존성으로 설치하지 않는다.
- 전체 도입, 디자인 토큰만 사용, Headless 컴포넌트 사용, 일부 컴포넌트만 채택과 자체 구현 중 가장 작은 적절한 범위를 고른다.
- 기존 프로젝트에 도입할 때는 현재 스타일과 컴포넌트를 먼저 조사하고 점진적 전환 범위와 롤백 방법을 정한다.
- 내부 토큰이나 안정성이 보장되지 않은 경로에 직접 의존하지 않는다.

## 4. 구현 전 결정할 사항

- 사용자가 화면에서 가장 먼저 알아야 할 정보와 가장 자주 할 행동
- 화면 밀도, 정보 계층, 콘텐츠 우선순위와 탐색 구조
- 브랜드 색상, 글꼴, 아이콘, 모서리, 그림자와 움직임의 원칙
- 모바일·태블릿·PC에서 유지하거나 달라질 구조
- 빈 화면, 로딩, 오류, 성공, 비활성화와 권한 부족 상태
- 키보드, 초점, 확대, 명도 대비, 터치 영역과 동작 줄이기 설정
- 의도적으로 피할 시각적 표현과 해당 프로젝트만의 고유 요소

## 5. 흔한 생성형 UI 패턴 점검

- 모든 정보를 같은 크기의 둥근 카드로 감싸지 않는다.
- 목적 없는 그라데이션, 유리 효과, 그림자, 배지와 장식 아이콘을 추가하지 않는다.
- 넓은 여백과 큰 제목이 실제 정보량이나 작업 흐름을 방해하지 않는지 확인한다.
- 대시보드, 3열 기능 소개와 반복 카드 구성을 프로젝트 성격과 무관하게 기본값으로 선택하지 않는다.
- 임의의 숫자, 후기, 회사 로고와 성과 지표를 화면을 채우기 위해 만들지 않는다.
- 시각적 새로움보다 사용자가 다음 행동을 이해하고 완료할 수 있는지를 우선한다.

## 6. 완료 확인

- 선택한 레퍼런스와 최종 결과가 닮은 이유가 복제가 아니라 명시한 설계 원칙에서 비롯됐는지 확인한다.
- 프로젝트 고유 요소가 색상 변경 외에도 정보 구조, 콘텐츠, 상호작용 또는 시각 언어에 드러나는지 확인한다.
- 지원 화면 크기와 주요 브라우저에서 실제 콘텐츠로 검증한다.
- 키보드 조작, 초점 표시, 확대, 대비와 상태 전달을 수동으로 확인한다.
- 디자인 시스템을 사용했더라도 접근성·반응형·브랜드 적합성을 자동 통과로 처리하지 않는다.
