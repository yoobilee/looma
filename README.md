# Looma

Looma는 QA 엔지니어가 프로젝트의 테스트 업무를 정리하고 이어가기 위한 개인 업무 도우미입니다. 기존 테스트 자산을 기준으로 요구사항의 변경, TC 검토, 수행 결과와 확인사항을 연결해 관리하는 한국어 웹앱을 만들고 있습니다.

## Looma가 다루는 흐름

```mermaid
flowchart LR
    A[산출물] --> B[요구사항]
    B --> C[테스트 조건]
    C --> D[TC]
    D --> E[수행 결과]
    E --> F[이슈와 기록]
```

변경된 산출물이 들어오면 기존 요구사항과 테스트 자산을 기준으로 영향을 살피고, TC 변경안을 검토한 뒤 반영하는 흐름을 지향합니다. 전체 TC를 다시 만드는 대신 기존 자산을 유지하면서 바뀐 부분을 이어가는 것이 목표입니다.

현재는 업로드한 문서 내용을 자동 분석해 요구사항이나 변경안을 생성하는 기능은 연결하지 않았습니다. 변경 영향 검토와 변경안의 검토 및 반영 흐름은 예시 데이터와 현재 프로젝트 데이터 구조를 통해 사용할 수 있습니다.

## 주요 기능

- **프로젝트와 테스트 자산** — 프로젝트별로 산출물의 파일 이름, 링크와 버전을 등록하고 요구사항과 TC를 확인합니다. 요구사항, 테스트 조건, TC의 연결을 관리하고 TC의 근거 산출물을 표시합니다.
- **요구사항 파일 가져오기와 기본 TC 초안** — 정리된 요구사항 표(CSV/XLSX)를 열 매핑과 미리보기를 거쳐 요구사항으로 가져옵니다. 요구사항 화면에서 요구사항과 테스트 관점을 골라 요구사항 문장만 근거로 한 기본 TC 초안과 테스트 조건을 만들 수 있으며, 미리보기에서 확인 필요 · 제외를 확인하고 같은 내용의 TC가 이미 있으면 기존 TC와 연결 · 별도 신규 · 제외 중에서 직접 고른 뒤에만, 미리보기와 같은 내용일 때만 저장합니다. 이 초안은 규칙 기반이며 AI가 만든 것이 아닙니다. 기존 TC는 바꾸지 않고, 고객사 TC ID는 만들지 않습니다.
- **변경 영향 검토** — 요구사항 변경과 TC의 신규, 수정, 유지, 폐기 제안을 검토하고 반영합니다. 중복 후보는 기존 TC 수정, 별도 생성, 제외 중 처리 방법을 사용자가 결정하며, 미결정 항목이나 판단 간 충돌이 있으면 반영을 막습니다.
- **TC와 수행 결과 가져오기** — CSV/XLSX의 열을 매핑하고 기존 TC와의 연결이나 변경 내용을 검토합니다. Excel 등에서 수행한 결과는 TC 정의를 바꾸지 않고 별도 기록으로 가져오며, PASS, FAIL, BLOCKED, 미수행을 기능과 플랫폼별로 요약합니다.
- **이슈와 확인사항** — FAIL · BLOCKED 결과나 수행 결과 비교의 신규 실패 · 계속 실패 · 신규 차단 행에서 결함(이슈)과 사양 · 정책 확인사항을 직접 만들어, 어떤 TC의 어느 차수 · 플랫폼 결과에서 나왔는지 연결해 둡니다. 상태는 확인 필요 · 해결됨 · 보류로 관리하며, 이후 차수에서 PASS가 나와도 자동으로 해결 처리하지 않습니다.
- **추적성과 이력** — 요구사항에서 테스트 조건과 TC로 이어지는 관계, 가져온 파일의 행과 TC의 연결을 유지합니다. 가져오기 이력과 프로젝트 활동 기록에서 처리한 내용을 다시 확인할 수 있습니다.
- **개인 작업공간** — 오늘의 할 일, 임시 메모, 용어 사전을 함께 제공합니다. 데스크톱 중심의 반응형 화면과 라이트/다크 테마를 지원합니다.
- **로컬 저장** — 앱 상태는 브라우저 IndexedDB에 저장하고, TC와 수행 결과 가져오기의 원본 파일 bytes는 별도 저장소에 보존합니다. 처음 실행할 때 예시 데이터를 만들며, 현재 서버 저장과 기기 간 동기화는 제공하지 않습니다.

## XLSX 가져오기와 내보내기

고객사에서 사용하는 XLSX 양식을 최대한 유지하기 위해, 가져온 원본 bytes를 보존하고 기존 행의 변경된 셀을 OOXML 수준에서 수정합니다. SheetJS는 파일을 읽고 결과를 확인하는 데 사용하며, 내보낼 때 전체 통합 문서를 SheetJS로 다시 쓰지 않습니다.

Looma에서 만든 신규 TC는 검토가 끝나고 다시 가져왔을 때 구별할 수 있는 경우에만 기존 표 끝에 추가합니다. 고객사 TC ID가 없으면 ID 칸을 비워 두며, Looma가 임의로 고객사 ID를 만들지 않습니다.

Excel 표(table), 자동 필터(autoFilter), 수식이나 병합 범위 등으로 새 행의 위치와 의미를 안전하게 유지할 수 없으면 행 추가를 막고 제외 이유를 표시합니다. 이때 기존 셀 수정이 안전하면 해당 수정만 내보낼 수 있습니다. 지원하지 않는 셀 수정이나 내보낸 파일의 재검증 실패는 다운로드를 중단하는 방식으로 처리합니다.

## 설계 원칙

- 기존 TC 세트를 지속적으로 유지하는 기준 자산으로 둡니다.
- 변경된 부분을 중심으로 제안을 검토하고, 명시적인 판단을 거쳐 반영합니다.
- 요구사항이 제거되어도 TC를 즉시 삭제하지 않고 폐기 여부를 별도로 검토합니다.
- 요구사항, 테스트 조건, TC 사이의 추적성을 유지하고 TC 정의와 수행 결과 기록을 분리합니다.
- 파일 구조를 안전하게 다룰 수 없으면 추측해서 내보내지 않습니다.

ISO/IEC/IEEE 29119의 테스트 설계 및 추적성 개념을 참고한 구조입니다.

## 기술 스택

- React, TypeScript, Vite, React Router
- CSS Modules와 CSS 변수 토큰, lucide-react, Pretendard
- IndexedDB, SheetJS, OOXML 수정 모듈
- Vitest, Playwright, GitHub Actions

## 실행 방법

Node.js 24와 npm을 사용합니다. Node 버전은 [`.nvmrc`](.nvmrc)에 지정되어 있습니다.

```bash
git clone https://github.com/yoobilee/looma.git
cd looma
npm ci
npm run dev
```

전체 검증을 실행하려면 Chromium 테스트용 브라우저를 먼저 설치합니다.

```bash
npx --no -- playwright install --only-shell chromium
npm run verify
```

## 검증

`npm run verify`는 Lint, Type Check, 단위 테스트, 브라우저 테스트, Build를 순서대로 실행합니다. Vitest로 변경안 반영, 파일 가져오기, 추적성, XLSX 수정과 신규 행 추가 등 도메인 로직을 검증하고, Playwright 기반 Chromium 테스트로 실제 IndexedDB의 저장과 트랜잭션 동작을 확인합니다.

GitHub Actions도 PR과 main push에서 같은 검증 명령을 실행합니다. 브라우저 자동 검증의 현재 범위는 IndexedDB 회귀 테스트입니다.

## 프로젝트 상태

개인 프로젝트로 개발 중입니다. 현재는 로컬 데이터 기반으로 QA 작업 흐름을 구현하고 있으며, 문서 분석과 AI 기반 변경안 생성은 아직 연결하지 않았습니다.
